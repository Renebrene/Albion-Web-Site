## Что проверено и в порядке

- Seq-токены против устаревших ответов геокодеров и подсказок (`addressRequestSeq`, `reverseRequestSeq`, `suggestSeq`).
- Debounce записи URL (300 мс) с каноническим сравнением (`canonicalQuery`) — двойного применения и циклов нет.
- Очистка всех таймеров/observers/listeners в `AdvertisingPage` (`onBeforeUnmount`) и в обоих движках карты (`destroyMap`).
- `accountSaveChain` — PUT портфеля строго по очереди, перезапись порядка исключена.
- Undo удаления в портфеле с восстановлением позиции и режима выбора.
- Singleton-стор синхронизирует счётчики портфеля (шапка/панель/чат) везде одинаково.
- Double-submit защищён `:loading` у QBtn (Quasar подавляет onClick при loading).
- Сброс кэша попапов (`clearPopupContentCache`) после обновления каталога выполняется по контракту.
- Инвалидация объектных URL в загрузках админки (`revokeQueuePreviews`, `onBeforeUnmount`).
- Группировка видеоэкранов: `groupSides` не отбрасывает индекс подписи («A» и «A(1)» — разные стороны), обе стороны рендерятся в попапе одной точки (решение владельца: один маркер на координату — дизайн).

## Рекомендации

### Производительность
1. Debounce поиска (200–250 мс) + при загрузке каталога строить `Map<id, normalizedHaystack>` — убирает 7×N вызовов `normalize()` на каждый символ.
2. Единый индекс конструкций `Map<id, item>` для `refreshPopupState`/`onDocumentClick`/попапов — сейчас линейные `find()` по каталогу на каждый клик.
3. Перенести `itemsKeyOf`-сравнение из Leaflet в Yandex-движок; rAF-троттлинг событий центра карты, одна подписка вместо двух.
4. `Promise.all` для независимых запросов в `HomeSlider.load`; предзагрузка фона i−1 (симметрично i+1).
5. Удалить 4 мёртвых home-компонента (~1570 строк); пагинация в `ConstructionMediaPicker`; пауза опросов при скрытой вкладке.

### UX
1. Главная сквозная проблема — **тихие провалы** (silent failure): единый механизм ошибок (`$q.notify`/баннер) для админ-конструкторов, автосохранения портфеля, ЛК, чата, дашборда. Половина «Высокого» — это silent failure.
2. Таймаут/AbortController + кнопка отмены для всех долгих операций (чат, экспорт, обновление БД); блокировать конкретную кнопку, а не всю панель.
3. Подтверждения опасных действий (сброс переопределений, очистка портфеля — с явным текстом «будет удалён и текущий») + `onBeforeRouteLeave` для dirty-форм.
