# Техническое описание проекта Albion

Документ описывает назначение, основные функции, архитектуру и требования к развёртыванию Albion. Для подробностей отдельных подсистем см. документацию в `doc/` и `deploy/README.md`.

## 1. Назначение

**Albion** — веб-приложение рекламной сети «Альбион» для представления рекламных конструкций, поиска доступных размещений и подготовки подборок для клиентов. В состав входят публичный сайт, интерактивная карта и список конструкций, портфель, умный чат и административная панель для управления контентом и базой конструкций.

## 2. Основные возможности

- **Публичный сайт:** главная страница, сведения о компании, новости, контакты и информационные страницы.
- **Каталог конструкций:** карта и список с фильтрами по типу, размеру, городу, адресу и другим характеристикам. На карте показываются размещение, фотографии/схемы, стороны конструкции и месячная доступность.
- **Картографические движки:** Leaflet с тайлами OpenStreetMap или Yandex Maps JavaScript API 2.1. При недоступности Яндекс-карты приложение может перейти на Leaflet.
- **Поиск:** API и поисковый движок для фильтрации каталога; версия поиска 2 поддерживает нормализованный каталог в памяти процесса.
- **Умный чат:** принимает запрос на обычном языке, извлекает параметры поиска, выполняет поиск существующими средствами и возвращает результаты, которые можно использовать в карте, списке и портфеле. LLM — необязательный вспомогательный этап; базовый чат опирается на детерминированный разбор и не требует LLM для каждого запроса.
- **Портфель:** выбор конструкций и месяцев, сохранение состояния в браузере, отправка заявки и экспорт подборки в документ или таблицу.
- **Администрирование:** управление контентом сайта, конструкциями и медиа, обновление каталога из Excel, резервные копии, статистика и журналы.
- **Кабинет пользователя:** серверная часть и таблицы сохранены, однако пользовательский интерфейс сейчас отключён флагом. Публичный портфель и чат работают без кабинета.

## 3. Архитектура

```text
Браузер (Quasar/Vue SPA)
        │ HTTPS: сайт, /api/*, /storage/*
        ▼
Nginx (TLS, раздача SPA, reverse proxy, rate limits)
        │ внутренний HTTP
        ▼
FastAPI / Uvicorn
   ├── API и сервисы: публичный сайт, админка, портфель
   ├── поисковый адаптер ──► движок albion-search
   ├── умный чат ──────────► Ollama локально ИЛИ облачный OpenAI-compatible API
   ├── импорт Excel ───────► staging ──► PostgreSQL
   └── медиа/архивы ───────► локальное файловое хранилище
        │
        ├── PostgreSQL 16 + PostGIS + pgcrypto
        └── storage/ и archive/
```

### Компоненты и технологии

| Компонент | Назначение / технология |
|---|---|
| Frontend | Quasar 2, Vue 3, Vite; SPA с history routing. |
| Backend | Python 3.12, FastAPI, Uvicorn, Pydantic v2. |
| Database | PostgreSQL 16, PostGIS, pgcrypto; доступ через psycopg3. |
| Поиск | Вендоренный движок `engine/` (`albion-search`) и адаптеры `backend/search/`. |
| LLM | Необязательный провайдер Ollama или OpenAI-compatible endpoint. |
| Файлы | `storage/` для медиа; `archive/` для архивов и резервных копий. |
| Reverse proxy | Nginx; TLS, SPA/API-проксирование и production rate limiting. |

## 4. Основные потоки работы

### Поиск по карте и списку

Frontend загружает каталог и настройки через API, применяет фильтры и отображает результаты на выбранной карте или в списке. Доступность рассчитывается по состояниям размещений и месяцам; детали карточек используют фотографии и схемы из хранилища.

### Умный чат

1. Frontend отправляет сообщение в `POST /api/chat/message`.
2. Backend сначала разбирает известные формулировки детерминированными правилами.
3. Если обычного разбора недостаточно и LLM включена, система может запросить извлечение поисковых полей. Для Ollama используется локальный `/api/chat`; для облачного провайдера — OpenAI-compatible endpoint.
4. Ответ LLM валидируется и нормализуется; допустимы только известные параметры поиска. Модель не выполняет SQL и не задаёт идентификаторы объектов.
5. Backend выполняет поиск в каталоге и формирует ответ по найденным данным. Необязательная генерация текста LLM не должна подменять результаты; при недоступности LLM используется обычный ответ.
6. Сессии чата по умолчанию используют PostgreSQL при доступной схеме. История и журнал ходов управляются отдельно.

LLM можно настроить отдельно для этапов **разбора запроса** и **формирования ответа**. При использовании облачного провайдера текст запроса покидает инфраструктуру Albion и отправляется провайдеру; проект удаляет из облачного запроса телефоны и e-mail, но это не является полной анонимизацией.

### Импорт каталога

Исходная Excel-выгрузка проходит стадии преобразования в JSON, подготовки staging, проверки/загрузки медиа, переноса данных в PostgreSQL и архивации. Импорт поддерживает dry-run; реальное изменение базы выполняется отдельным подтверждённым режимом. Медиа хранятся в файловой системе, а их метаданные — в БД.

### Портфель и экспорт

Выбранные поверхности и месяцы хранятся в браузере. Экспорт выполняет backend и возвращает файл. Поддерживаются табличные, текстовые и офисные форматы; для ряда конвертаций требуется LibreOffice, для PDF — также доступный кириллический шрифт.

## 5. Технические требования

### Обязательное программное окружение

| Требование | Значение |
|---|---|
| Серверная ОС | Linux-сервер; документация предполагает VDS/systemd, конкретный дистрибутив и версию не фиксирует. |
| Python | 3.12 (ограничение проекта — `>=3.12,<3.13`). |
| Node.js | 22 для установки зависимостей и сборки frontend; на production запускается собранный SPA, а не dev-сервер. |
| БД | PostgreSQL 16 с PostGIS и `pgcrypto`; в документации схемы указана PostGIS 3.4.2. |
| Веб-сервер | Nginx рекомендуется для production: HTTPS, SPA и проксирование API/файлов. |
| Экспорт | LibreOffice для DOC/ODT/RTF/XLS/ODS и ряда PDF-сценариев; кириллические шрифты DejaVu/Liberation/Noto для PDF. |

Docker/Compose не является описанным основным способом развёртывания. Проект документирует запуск сервисов Linux через systemd и проксирование через Nginx.

### Аппаратные требования

Проект **не задаёт официальные минимумы CPU, RAM, диска или GPU**. Их нужно выбирать по количеству пользователей, объёму базы и медиа, числу Uvicorn workers, размеру модели и требуемой параллельности.

Практический начальный ориентир для небольшого production-развёртывания на одной машине (не официальный минимум):

- **CPU:** 8 современных ядер.
- **RAM:** 32 ГБ.
- **Диск:** NVMe от 500 ГБ как стартовый запас, затем увеличить с учётом фактических `storage/`, БД и архивов.
- **GPU:** нужна только для локального инференса на ускорителе. Для планирования можно рассматривать GPU с 12 ГБ VRAM, но совместимость и скорость Yandex-модели следует подтвердить на выбранной сборке. Без GPU локальный инференс возможен на CPU, но будет медленнее.

Это рекомендация для планирования, а не результат официального нагрузочного теста всего сайта. Размер файла модели не равен требованию к VRAM: на потребление памяти влияют квантование, контекст, рабочие буферы и параллельные запросы.

## 6. Варианты размещения LLM

### Локальная модель через Ollama

- Ollama и модель размещаются на сервере Albion или на отдельном GPU-сервере.
- Backend обращается к заданному `ALBION_CHAT_LLM_BASE_URL`; локальный адрес по умолчанию — `http://127.0.0.1:11434`.
- GPU не обязательна, но желательна для производительной обработки.
- В документации проекта упомянута YandexGPT-5-Lite-8B-instruct Q4_K_M, модель около 4,6 ГБ на диске, контекст 32k. Это размер файла/параметр контекста, не установленный минимум памяти.
- Ollama API следует оставить на loopback или закрыть внутренней сетью и firewall; не публиковать в интернет.

### Облачная модель

- GPU и установка модели на сервере Albion не требуются.
- Backend должен иметь исходящий HTTPS-доступ к API провайдера.
- Нужны API endpoint, имя модели, API-ключ и поддержка OpenAI-compatible формата.
- Ключ хранится только на backend в секретах окружения; его нельзя помещать во frontend-бандл или репозиторий.
- Нужно учитывать тарифы, лимиты, квоты, задержку, доступность сервиса и требования к передаче пользовательских данных.
- Облачная LLM — дополнительная внешняя зависимость; основной поиск и детерминированная логика остаются на стороне Albion.

При раздельном размещении приложения и Ollama соединение между ними должно проходить только по приватной сети с ограничением доступа от backend-хоста. При нескольких Uvicorn workers суммарное число запросов к одной GPU может быть больше установленного лимита на процесс; параллельность нужно проверять и ограничивать на уровне всей системы.

## 7. Сеть, эксплуатация и безопасность

- Публичный трафик направлять через Nginx по HTTPS; обычно доступны входящие 80/443 для редиректа и TLS.
- Uvicorn слушает внутренний адрес/порт, типично 8000. **Не открывать порт 8000 наружу.** Порт 9000 относится к frontend dev-серверу и не используется как production-сервер.
- PostgreSQL и Ollama не должны быть публично доступны; для удалённого Ollama разрешать соединения только от backend в приватной сети.
- Настроить `ALBION_ALLOWED_ORIGINS`, лимиты запросов в Nginx, резервное копирование БД и каталогов с медиа; регулярно проверять восстановление.
- Секреты и пароли хранить в окружении/защищённых файлах с ограниченными правами, не в Git.
- Yandex Maps требует действующий ключ, ограниченный разрешённым доменом; при недоступности карта может работать на Leaflet/OSM. В браузере нужен интернет для картографических ресурсов.
- Коммерческое использование локальной Yandex-модели требует проверки условий её лицензии.

## 8. Развёртывание (высокоуровнево)

1. Подготовить Linux-хосты, DNS/домен, HTTPS и закрытые сетевые соединения между компонентами.
2. Установить PostgreSQL 16, PostGIS и `pgcrypto`; создать базу и пользователя приложения.
3. Установить Python 3.12, установить backend-зависимости и задать секреты/параметры подключения в защищённом окружении.
4. Выполнить идемпотентные миграции БД отдельным шагом.
5. Установить Node.js 22, собрать frontend (`cd frontend && bun run build` либо используемый в проекте менеджер пакетов) и настроить production-раздачу SPA через Nginx.
6. Установить systemd-службу backend/Uvicorn. Проверить, что порт приложения доступен только локально/из доверенной сети.
7. Если используется Ollama — установить её и нужную модель, настроить URL для backend и проверить фактическую загрузку/задержки. Если облачная LLM — внести endpoint, модель и API-ключ в серверную конфигурацию.
8. Настроить Nginx, TLS, ограничения запросов, каталоги `storage/` и `archive/`, ротацию журналов и резервное копирование.
9. Проверить публичные страницы, карту, фильтры, импорт/медиа, умный чат с LLM и без неё, экспорт документов и процедуру восстановления резервной копии.

Конкретные команды, переменные окружения и systemd-примеры приведены в [`../deploy/README.md`](../deploy/README.md).
