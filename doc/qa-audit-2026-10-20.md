## 3. Критические находки

### P0-1. Открытые секреты в рабочем дереве

- `ChatGPT-САЙТ 6-20261005-2152.md` (102 419 строк) содержит открытый пароль
  администратора и команды входа; 5 вхождений строки с паролем
  (строки 99821, 99829, 99841, 100720, 100753).
- `202610180134.env` содержит `PASSWORD` и `SECRET` в открытом виде.
- Оба файла **не отслеживаются git, но и не игнорируются** (`.gitignore`
  покрывает `.env` и `.env.*`, но не `*.env` и не имя файла промта).

Риск: случайный `git add .` опубликует пароль и секреты. Действия:
1. Немедленно сменить пароль администратора панели и все секреты из `*.env`.
2. Убрать файлы из каталога проекта (в защищённое хранилище/архив).
3. Добавить в `.gitignore` минимум `*.env` и `ChatGPT-*.md`.
4. Проверить историю git на случай, если файл уже коммитился.

### P0-2. Потеря старых медиа при неудачном скачивании

Требование промта: если часть ссылок не скачалась — оставить старые файлы.
Фактически:

- `backend/importer/staging_to_postgres.py:550-570` — медиа с ошибкой
  пропускаются без fallback на старую версию;
- `backend/importer/import_pipeline.py:524-530` — storage предыдущего импорта
  удаляется после коммита.

Итог: недоступная ссылка приводит к исчезновению фото/карты. Это потеря
отображаемых данных и расхождение с явным требованием.

### P0-3. Прямые ссылки не с Яндекс.Диска не поддерживаются

`backend/importer/construction_media_downloader.py:226-244` отправляет любую
ссылку в `cloud-api.yandex.net`. Классификация `direct_url` есть в
`backend/importer/constructions_validate.py:19-37`, но downloader её не
использует. Прямые ссылки с других сервисов не скачаются.

## 4. Высокие находки

### P1-1. Проект позиционируется как Yandex Maps, но активен OSM

- `README.txt:3` утверждает «Yandex Maps JavaScript API v3»;
- `frontend/src/config/mapConfig.js:6,18` и загрузчик используют **2.1**;
- `backend/services/settings_service.py:107` — `map_engine` по умолчанию `osm`;
- фактический `GET /api/settings` вернул `map_engine: "osm"`, карта — Leaflet/OSM.

Нужно определить целевое требование: если демо должно показывать Яндекс.Карты,
включить `map_engine=yandex`, проверить ключ/Referer и привести README/код к
одной версии API. Если OSM — исправить README и название демо.

### P1-2. «Показать на карте» из чата пересекается с активными фильтрами

`openChatResults` (`SmartChatPanel.vue:477-489`) сохраняет id результатов и
переходит на `/vozmozhnosti?chat=1&mode=map`. На странице
`AdvertisingPage.vue:1335-1347` id чата фильтруются **поверх** текущих
фильтров (`filteredConstructions`). Если на сайте был выбран город/формат,
несовместимый с запросом чата, пересечение пустое: счётчик 0, маркеров нет.

Воспроизведено: при активном фильтре «Ростов, все форматы кроме Щитов» чат
нашёл 146 щитов, но карта показала 0 до полной перезагрузки страницы. После
reload фильтры сбросились и появились 146 результатов. Исправление: при
`chat=1` либо игнорировать посторонние фильтры, либо явно сбрасывать их под
параметры запроса и показывать плашку «Фильтры чата».

### P1-3. «Новый чат» после reload открывает старую переписку

`useChatWorkspace.js:16,62-66` не сохраняет список чатов и начинает `sequence`
с нуля. После reload создаётся ключ `chat-1`, а `useSmartChat.js:18,28`
поднимает из `sessionStorage` старую историю по этому ключу.

Воспроизведено на `/chat`: после reload и нажатия «Новый чат» появилась
предыдущая переписка. Риск: пользователь видит чужую/старую историю в
«новом» чате. Исправление: хранить список чатов и счётчик в `sessionStorage`
или использовать уникальные ключи (`crypto.randomUUID()`).

### P1-4. Заглушки в публичной навигации

- `/napravleniya` («ДЕЯТЕЛЬНОСТЬ») — «Раздел находится в разработке»
  (`frontend/src/pages/DirectionsPage.vue`).
- `/informaciya`, вкладка «ОБЩЕЕ» — «Раздел находится в разработке».
- Соцсети VK/OK/Макс — `href="#"` (`AppHeader.vue:103,108,116`).
- Все ссылки подвала — `href="#"` (`AppFooter.vue`).
- В режиме точки поиск по адресу прямо помечен «подключим позже (по
  геокодеру)»; ввод адреса не даёт результата (`AdvertisingPage.vue:1431-1439`).

Для публичного сайта это выглядит как нерабочие элементы. Нужно либо
реализовать, либо скрыть/задизейблить с понятным статусом.

### P1-5. Нет loading/error-состояний; ошибка выглядит как «ничего не найдено»

- `HomeSlider.vue:920-928`: при сбое `/api/home` главная остаётся пустой.
- `AdvertisingPage.vue:1957-1985,585-591`: при ошибке `/api/constructions`
  показывается 0 и «Ничего не найдено».
- `ContactsPage.vue`: при сбое — пустая страница.

Нужны отдельные состояния `loading / error / empty`, скелетоны и кнопка
«Повторить». Empty нельзя показывать до завершения загрузки.

### P1-6. Клавиатурная доступность ключевых сценариев

- Месяцы в карточках списка и попапах карты — `div` без `role/tabindex`,
  `AdvertisingPage.vue:409-480`, `popupContent.js:73,141,414`.
- Карточки новостей — `<article @click>` без ссылки/фокуса,
  `NewsCard.vue:1-5`.
- Фото карточки — `<img @click>` без кнопки, `AdvertisingPage.vue:345-352`.
- Мишень точки — pointer-only, `AdvertisingPage.vue:96-120`.
- У поисковых полей убран `outline` без `:focus-visible`
  (`MapSearch.vue:120-131`, `HomeSearch.vue:172-182`).
- Часть вторичного текста имеет контраст ниже 4.5:1
  (`app.scss`, `AppHeader.vue:573-579`, `InfoPage.vue:317-327` и др.).

Это блокирует сборку портфеля и чтение новостей без мыши.

### P1-7. Форма обратной связи без клиентской валидации

`HomeSlider.vue:495-534,1113-1136`: пустая отправка уходит на сервер,
возвращается `400`, а пользователь видит общее «Не удалось отправить».
Нужны `required`, маска телефона, подсветка полей и вывод `detail` от API.

## 5. Средние находки

### P2-1. Фильтр точки молча действует на карту и список

После «Зафиксировать» переключение на «Интерактивную карту»/«Список»

### P2-2. «Снять все» в городах оставляет Ростов-на-Дону

`FiltersSidebar.vue:229-233` вместо пустого набора выбирает Ростов (или `[]`).
Кнопка называется «Снять все», но снимает не все. Нужно либо переименовать в
«Только Ростов», либо разрешить пустой набор и трактовать его как «все».

### P2-3. Расхождения с промтом по админке и импорту

По статическому сравнению `ChatGPT-САЙТ 6-...md`:

- нет загрузки **карты** отдельным IMG-блоком (есть только фото);
- нет просмотра/скачивания фото из админ-каталога;
- нет подгрузки по 30 карточек (рендерятся все);
- нет редактирования координат;
- произвольные дополнительные поля не сохраняются (только `number/district`);
- город и сторона — жёсткие списки, не справочники БД;
- не вычисляется/не показывается соотношение сторон фото;
- загруженный Excel не переименовывается в дату-время;
- retention архиев не отделяет успешные от прочих;
- компактный режим не скрывает тип/размер;
- нет общего progress bar обновления базы;
- автоматический откат при ошибке — только для критических сбоев PostgreSQL.

Часть этих пунктов сам промт позже отменяет или переформулирует. Нужен
канонический список подтверждённых требований (см. раздел 8).

### P2-4. Месяцы портфеля зависят от посещения `/vozmozhnosti`

`PortfolioPanel.vue` использует глобальный `MONTHS`, который заполняется
побочным эффектом `AdvertisingPage.vue:1965`. При прямом заходе на `/portfolio`
после reload полный список месяцев может быть пуст (`constructionGroups.js:47-90`).

### P2-5. URL-синхронизация на каждый символ и scroll-to-top

`AdvertisingPage.vue:1689-1749` вызывает `router.replace` при каждом вводе;
`router/index.js:28` на каждой навигации делает scroll вверх. На мобильном это
даёт скачки при вводе адреса. Нужен debounce 300–500 мс или запись по Enter/blur.

### P2-6. Виртуальный список с фиксированной высотой

`AdvertisingPage.vue:225-235` использует `virtual-scroll-item-size="820"`, хотя
высота карточки переменная (число сторон, фото, колонки). Возможны скачки и
пустые области. Нужно динамическое измерение.

### P2-7. Производительность

- `/api/home` выполняет несколько запросов на каждый вызов, кэша нет; под
  40 параллельными запросами медиана выросла до ~569 мс.
- `/api/constructions` отдаёт ~2,4 МБ JSON (gzip включён); стоит проверить
  brotli/кэш на nginx.
- `AppHeader` и `AppFooter` независимо запрашивают `/api/site-menu`.
- Чанк `AdvertisingPage` — ~197 КБ (59 КБ gzip), общий JS — ~952 КБ.
- PostgreSQL не является узким местом: cache hit >99,5%, 0 temp-файлов;
  `work_mem=4MB` достаточно. Подробности — `doc/postgresql-tuning.md`.

### P2-8. Документация API и SEO

- `/docs` и `/openapi.json` публично доступны (200).
- `useSeo.js` применяет `index, follow` и к админке/404; пустые meta не удаляют
  старые значения.
- Нет `h1` на `/kontakty`; в режиме карты на `/vozmozhnosti` тоже.
