## 4. Рекомендации

### 4.1. Производительность

1. **Виртуализация длинных списков.** Два места критичны: список конструкций (`AdvertisingPage.vue`, до ~1500 карточек с 12 кнопками месяцев каждая) и панель портфеля (до 500 позиций). «Показать ещё» лишь наращивает окно — старые строки не выгружаются. Нужен `vue-virtual-scroller` (`DynamicScroller`) либо выгрузка строк выше вьюпорта.
2. **Разделить Leaflet и общий код.** `popupContent.js` → `markerIcon.js` → `import L from 'leaflet'` тянет ядро Leaflet (≈100 КБ) в чанк страницы. Достаточно вынести `escapeHtml` в `utils/escapeHtml.js` — и динамический импорт движка снова начнёт работать так, как обещает комментарий в `MapView.vue`.
3. **Кэшировать статус доступности.** `getAvailabilityState` парсит строки на каждой пересборке выборки — до ~18 тыс. раз за изменение фильтра. Построить один раз на загруженный каталог `Map<item, Map<month, state>>` и пересчитывать только при смене данных. То же для `markerColor` (10-20 тыс. вызовов на рендер) и для `signatureOf` в `popupContent.js`.
4. **Убрать reflow на каждом кадре карты.** `getBoundingClientRect()` + `getCoordinatesAtScreenPoint` на каждый `map-center` → принудительный reflow дважды за кадр. Координаты считаются из центра карты без обращения к DOM.
5. **Троттлить скролл-события.** `onListScroll` пишет в реактивное состояние на каждом событии → полный ререндер списка на каждом кадре. Запись через rAF, догрузка — через `IntersectionObserver`.
6. **Стабильные ключи в `v-for`.** Ключ строки сетки включает индекс (`${items[0]?.key}|${i}`) — любое изменение состава пересоздаёт DOM всех строк вместе с картинками.
7. **Параллельные запросы на главной.** `/api/home` → `/api/about` → `/api/constructions/stats` → `/api/news` идут последовательно — hero сначала рисуется неполным, потом перерисовывается.
8. **Снять `psutil.cpu_percent(interval=0.1)` из `create_media_category`** — вызов блокирует поток на 100 мс при создании каждого раздела.
9. **Ленивые попапы для Yandex.** Настройка `map_lazy_popups` работает только в Leaflet; в Яндексе ~600 попапов строятся за один кадр.

### 4.2. UX

1. **Единый контракт «пусто/ошибка/загрузка»** во всех трёх режимах карты: оверлей «Ничего не найдено» с кнопкой сброса (сейчас есть только в режиме «Список»), единый формат ошибок вместо браузерного «Failed to fetch».
2. **Согласованные счётчики.** Сейчас «N рекламных сторон» считает поверхности, список рисует стороны, карта — точки. Три величины под одной подписью — для призматрона счётчик завышен втрое.
3. **Feedback на все асинхронные действия.** Индикатор «ассистент печатает» + `aria-busy` в чате; тост «Фильтры сброшены»; подтверждение сброса фильтров (как в портфеле); индикатор загрузки карты и фото.
4. **Не терять контекст при обновлении.** Автопрокрутка чата только если пользователь был внизу; не затирать локальные чаты серверным списком; не сбрасывать несохранённый `draft` при перемонтировании панели.
5. **Единые правила для фильтров.** «Показать все» для месяцев и форматов (сейчас только для городов); строка «Активные фильтры: N» с быстрым сбросом; снятие одного фильтра без сброса остальных; пояснение, что фильтр по месяцам календарный.
6. **Клавиатурная доступность.** `Enter` на «Умный чат» не работает (конфликт с Quasar `keyup`); глобальный `keydown` в `HomeSlider` перехватывает стрелки у просмотрщика фото и у `<select>`; подсказка «И / ИЛИ» доступна только мышью; переключатель вкладок без `role="tab"`.
7. **Доступность контента.** `alt=""` у фото конструкций; `aria-live` для счётчиков и сообщений формы; `aria-labelledby`/`focus-trap` для модалки гео-региона, которая к тому же сейчас не перекрывает шапку.
8. **`prefers-reduced-motion`.** Комментарий в `HomeSlider.vue:282` описывает несуществующее поведение — медиазапроса в файле нет; `NewsMediaCarousel` тоже не гасит переход.

### 4.3. Архитектура

1. **Один источник истины для состояния фильтров.** Сейчас URL и reactive-состояние конфликтуют: `applyFiltersFromUrl()` перезаписывает живой выбор при любом изменении `route.query`, обратная запись идёт с debounce 300 мс. Нужен явный разбор: свои изменения → пишем в URL; внешние (popstate, `pf`, `chat`) → применяем. Плюс версионирование состояния, чтобы откатить нельзя было.
2. **Разделить «не выбрано» и «нечего показать».** Пустой массив фильтра сейчас означает «показать всё»; этим же пользуются «чистилки» исчезнувших значений → фильтр молча выключается. Нужен явный флаг применения фильтра.
3. **Разделить источники доступности.** `statuses` (состояние) и `months` (сырой текст/проценты) — разные данные в одном поле. Сейчас `months` перекрывает `statuses` через `??`, из-за чего админский статус месяца не доходит до сайта.
4. **Вернуть единый `adminFetch`.** 12 админских запросов идут мимо него через сырой `fetch` → нет единой реакции на 401.
5. **Убрать мёртвый код.** `markerIcon.js` (не вызывается, содержит расходящуюся логику цвета), `EssentialLink.vue` (не используется), `isAdmin` в `AppHeader.vue`, ветка «откат на адрес» в `constructionKey` (недостижима), отладочный `psutil` в `create_media_category`.
6. **Разделить «представление» и «состояние» портфеля.** Панель монтируется в 2-3 экземплярах, у каждого свои тосты и черновики названия → нужен общий стор.
7. **Единый источник месяцев.** `MONTH_ORDER`/`MONTH_SHORT` продублированы с разными подписями («янв. 2026» / «ЯНВ»); глобальный `MONTHS` импортируется напрямую в компоненты.
8. **Ключи хранилища — по пользователю.** Метки удаления портфеля лежат в общем `albion_portfolio` и переживают выход из аккаунта → следующий пользователь браузера теряет часть сохранённого.
9. **Общий стор для данных, загружаемых дважды.** `/api/site-menu` запрашивается шапкой и подвалом параллельно на каждой странице.
