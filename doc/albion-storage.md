# Внутреннее хранилище сайта на Albion

Медиатека сайта (изображения, видео, документы из админки) умеет хранить файлы
на файлохранилище Albion. Старое локальное хранилище остаётся рабочим: режим
переключается в админке, а локальная копия пишется всегда.

Общий контракт токенов и endpoint'ов —
`/home/alexice/projects/PhotoBAse/scene_fingerprint_RELEASE_v38_1_v33_20260815_1912 (2)/docs/integration/01_albion_tokens.md`.

## 1. Режимы

| Режим | Запись | Публичный URL |
|---|---|---|
| `local` (по умолчанию) | только `storage/media/` | `/storage/<path>` |
| `albion` | локально **и** в Albion | `external_url` из Albion; если его нет — `/storage/<path>` |

Локальная копия в режиме `albion` обязательна: `portfolio_export`, бэкап,
импорт конструкций и старые записи продолжают читать её без изменений.

## 2. База данных

Миграция аддитивная и идемпотентная:

```bash
.venv/bin/python -m backend.migrations.migrate_media_external_storage
```

Добавляет в `media` и `media_variants`:

- `storage_backend` — `local` (default) или `albion`;
- `external_url` — публичная ссылка Albion;
- `external_key` — идентификатор объекта для удаления.

Backfill не нужен: старые строки получают `local` через DEFAULT. **Без
миграции приложение не запустится**: запросы списка медиа уже читают новые
колонки. Откат — после переключения в `local` удалить колонки отдельной
миграцией (в текущем релизе не требуется).

## 3. Настройка

1. В Albion выпустить токен с правом `upload` (и, желательно, `delete`),
   привязанный к папке:

```bash
python manage_tokens.py add "Сайт Альбион" --scopes upload,delete --folder <uuid>
```

2. Админка сайта → **Настройки** → блок **«Файлохранилище Albion»**:
   режим, URL, ID папки, TTL, токен. Кнопка «Проверить связь» вызывает
   `/api/v1/integration/verify`.
3. Переключить режим на `albion` и сохранить.

Секреты хранятся в `site_settings` (ключ `storage.albion`), а не в публичной
схеме настроек, и возвращаются только маской. Env-fallback:
`ALBION_FILES_URL`, `ALBION_FILES_TOKEN`, `ALBION_FILES_FOLDER_ID`,
`ALBION_FILES_MODE`, `ALBION_FILES_TTL_DAYS`.

## 4. Как это работает

- `save_image` / `save_video` / `save_document` сначала пишут локальные файлы и
  строки БД, затем (в режиме `albion`) отправляют каждый созданный объект
  (основной файл, варианты `large/card/thumb`, превью видео) в Albion.
- При успехе строки получают `storage_backend='albion'`, `external_url`,
  `external_key`; ответ API содержит `url` для медиа и каждого варианта.
- При ошибке Albion загрузка **не падает**: файл остаётся локальным,
  `storage_backend='local'`, в лог пишется предупреждение. Это осознанный
  fail-open: потерять загруженный пользователем файл хуже, чем не отправить
  копию в облако.
- Удаление: локальные файлы удаляются как раньше; объекты Albion — только если
  у токена есть `delete`. Иначе в логе остаётся предупреждение об «осиротевшем»
  объекте, а операция считается успешной.

## 5. Откат

- Переключить режим на `local` в админке — старые локальные URL восстанавливаются
  сразу для строк `media`; уже сохранённые абсолютные URL в контенте (контакты,
  меню) не переписываются.
- Очистить токен/URL — новые загрузки пойдут только локально.
- Данные не удаляются: локальные копии всегда на месте.

## 6. CSP

Публичные ссылки Albion открываются как изображения/видео. Хост хранилища
должен быть в `img-src`/`media-src`:

- `frontend/index.html` (meta-CSP);
- `deploy/nginx.conf.example` (заголовок CSP).

В примерах стоит `https://media.albion.example.ru` как заглушка. Замените её на
реальный домен из `ALBION_FILES_URL`; иначе браузер заблокирует внешние файлы.

## 7. Ограничения v1

Не переведены на Albion и продолжают работать локально:

- импорт конструкций (`storage/constructions/imports/...`, `construction_media`);
- вложения новостей (`news_media`);
- изображения контактов и geo-слайдов, хранящие путь отдельно от `media`;
- `portfolio_export` и `site_backup` читают локальные копии — это осознанно;
- backfill существующих файлов и удаление локальных копий не выполняются.

Превью видео загружается в Albion, но отдельной строки в БД для него нет,
поэтому в списках остаётся локальный `preview_path`.

## 8. Проверки

```bash
.venv/bin/python -m pytest backend/tests -q
cd frontend && bun run build && bun run lint:check
```

Тесты `backend/tests/test_albion_storage.py` покрывают миграцию, маскировку
токена, `local`/`albion`, успешную и неуспешную загрузку, удаление и проверку
связи без сети.
